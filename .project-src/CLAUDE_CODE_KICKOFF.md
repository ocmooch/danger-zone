# Claude Code Kickoff

This document is what you copy/paste (or attach) when starting your first Claude Code session for Phase 1.

---

## How to use this

**Recommended approach: start a single, long-running Claude Code session per milestone.** Each milestone in `docs/09_ROADMAP.md` is sized to fit a coherent session.

### Step 1 — Prep your terminal

```bash
cd ~/code/fantasy-football   # or wherever you put the project
# Verify your prereqs:
ls .env                       # exists and is populated
cat .env | grep NFL_LEAGUE_ID # shows your real league ID
ls docs/                      # all 10 design docs are present
python3 --version             # 3.11 or newer
uv --version                  # installed
```

### Step 2 — Start Claude Code

```bash
claude
```

### Step 3 — Paste the kickoff prompt below

The first message of the session sets context. Use the version that matches your starting milestone.

## Sanity checks for each session

Before declaring a milestone complete, confirm:

- [ ] All tests pass: `uv run pytest`
- [ ] Lint clean: `uv run ruff check`
- [ ] Format clean: `uv run ruff format --check`
- [ ] Types clean: `uv run mypy src/`
- [ ] The milestone's "Done when" checklist in `docs/09_ROADMAP.md` is satisfied
- [ ] You've manually run the new feature once to verify it works end-to-end
- [ ] Changes committed with a descriptive message

## Useful interactive prompts mid-session

When you want Claude Code to do something specific:

- **When stuck on a parser**: "Save the current HTML response from {URL} to `tests/fixtures/nfl_com_html/{name}.html` so we have a snapshot to debug against."
- **When the scoring engine disagrees with NFL.com**: "Show me the full breakdown for this stat line: pull the raw stats, run them through the engine, and print every rule that fired with its sub-total."
- **When checking data quality**: "Write a one-off SQL query to find every player with non-zero stats but a NULL `gsis_id` — these are the ID mapping failures."
- **When NFL.com breaks**: "The `/league/{id}/history/{year}/transactions` parser stopped returning data. Read `tests/fixtures/nfl_com_html/transactions/` — the older snapshot — compare to a fresh fetch I just made, and identify what changed."

## What I expect Claude Code NOT to do

To save you headaches:

- Don't add dependencies that aren't in `pyproject.toml` without asking
- Don't change the package layout from what's in `docs/02_ARCHITECTURE.md`
- Don't add new SQL features that work in SQLite but break PostgreSQL (or vice versa)
- Don't commit the `.env` file (gitignored, but worth saying)
- Don't print/log the NFL_COOKIE value, ever
- Don't make live HTTP calls in unit tests (use fixtures)
- Don't merge milestones — finish each one cleanly before starting the next
- Don't update Python or major dependency versions mid-project

## Recovering from a stuck session

If Claude Code gets confused or goes in circles:

- Stop. Don't let it dig deeper.
- Type `/clear` (or quit and restart)
- Start a fresh session
- Reference the specific commit + the specific milestone you're stuck on
- Be precise about what's broken: paste the actual error, not a paraphrase
